## 1. .pak 容器格式逆向结论（源码→字段对照）

任务原文猜测的 `pakfile.cpp/h` 在该仓库**不存在**——.pak 容器读取代码是 `MCLib/Packet.cpp`
+ `packet.h`（PacketFile 类）；`MCLib/ffile.cpp/h + ffent.h`（FastFile 类）是**另一种容器**
（.ff 资产库，elfHash 索引），官方任务 .pak 不使用它。本切片实现 PacketFile。

### 1.1 PacketFile 二进制布局（packet.h `PACKET_FILE_VERSION=0xFEEDFACE`）

小端序。`Packet.cpp::afterOpen/seekPacket/readPacket` 逐字段对照：

| 偏移 | 类型 | 字段 | 源码依据 |
| --- | --- | --- | --- |
| 0 | u32 | 0xFEEDFACE（否则视为 checksum：`sum(bytes[4:]) mod 2^32` 校验，Packet.cpp:156-167/checkSumFile:125-146） | afterOpen |
| 4 | u32 | firstPacketOffset = `(2 + numPackets) << 2` | reserve:531 / afterOpen:171 `numPackets = firstPacketOffset/4 - 2` |
| 8 | u32 × numPackets | seek table：**bit29-31 = storage type，bit0-28 = packet 起始偏移**（OFFSET_MASK=0x1FFFFFFF，TYPE_SHIFT=29） | packet.h:44-50 |
| firstPacketOffset | — | packet 数据区 | seekPacket |

- **packetSize = 下一 entry 的 offset − 本 entry 的 offset**（最后一个 packet 到文件尾，
  seekPacket:422-429）；NUL(7) 类型为空 packet。
- packet 数据（packet.h:34-39 类型表）：RAW=0 / FWF=1（file-within-file，按 RAW 读）/
  LZD=2 / HF=3 / ZLIB=4 / NUL=7。
- **LZD/ZLIB：packet 首 u32 = unpackedSize，其后是压缩体**（packetSize 含该 4 字节头，
  seekPacket:434-444 + readPacket:300-360）；ZLIB = 标准 zlib `uncompress`（Python
  `zlib.decompress` 直解），解压长度必须等于 unpackedSize。
- HF：原版代码即 `STOP("No Longer Supported!!")`（readPacket:363-365）；LZD 旧 LZ 算法
  （lzdecomp.cpp）。**实测 tut_01/mc2_01 两关全部 packet 只有 RAW/ZLIB**（751 ZLIB +
  266 RAW / 1449 ZLIB + 457 RAW，无 LZD/HF）→ Python 侧 LZD/HF 显式抛错（裁剪 §6.5）。

### 1.2 packet 0 = 地形高程（Terrain.cpp + mapdata.cpp + Vertex.h）

- `realVerticesMapSide = sqrt(packetSize / sizeof(PostcompVertex))`（Terrain.cpp:293-294），
  原版支持 60/80/100/120；`PostcompVertex = 32 字节`（Vertex.h:32-53，16 字节对齐）：
  `vertexNormal 3×f32(12B) + elevation f32 + textureData u32 + localRGBLight u32 +
  terrainType u32 + selected/water/shadow/highlighted 4×u8`。
- `MapData::newInit`（mapdata.cpp:146-153）整包直读为 PostcompVertex 数组——高程即
  每**顶点**一个 f32（米级原始值）。
- `worldUnitsPerVertex = 128.0`（Terrain.cpp:76）；tile = 相邻顶点围成的格，
  **tiles/边 = vertices − 1**（dterrain.h TILESPERSIDE）。
- 世界坐标 ↔ tile（Terrain.cpp:265-268）：`tileCol = (x + worldUnitsMapSide/2)/128`、
  `tileRow = (worldUnitsMapSide/2 − y)/128`（y 轴向南递减行号）。

### 1.3 packet 1 = 静态对象布置表（objmgr.cpp countTerrainObjects:781-856）

- 首 i32 = totalObjCount；每记录 **40 字节 = 10×i32**（8 字段 + 2 个注释标明的 padding
  long）：`objTypeNum(i32), x/y/z(f32×3), rotation(f32 度), damage(i32), teamId(i32),
  parentId(i32), padding 2×i32`。
- **实测验收证据**：mc2_01.pak packet 1 unpackedSize=40004 = `4 + 1000×40` 精确吻合；
  tut_01.pak = `4 + 4×40 = 164` 精确吻合。
- 该 packet 只装**静态物**（树/建筑/桥/门/炮塔——countObject:858-900 的 switch 对
  BATTLEMECH 等 mover 类直接 Fatal），机甲/载具布置不在 pak。

### 1.4 objTypeNum 解析表 = Data/Objects/object2.pak

- mission.cpp:2139 `ObjectManager->init("object2", ...)` → objtype.cpp:221-230
  `objectPath + "object2" + ".pak"`——类型表本身也是 PacketFile，
  **packet N = objTypeNum N**，内容为 FITini 文本，`[ObjectClass] l ObjectTypeNum` =
  对象类号（与 Data/Objects/*.fit 主表同编号：2=BATTLEMECH / 3=GROUNDVEHICLE /
  21=TURRET / 0=树 / 1=建筑…），objtype.cpp:356-373 按 ObjectTypeNum 分派创建。
- 实测 object2.pak：1188 packets，类分布 2(机甲)=34、3(载具)=62、21(炮塔)=34、
  0(树)=88、1(建筑)=325 等。
- 静态对象类名（packet [ObjectType] st Name）实测：290="Nav1"（建筑）、135/531/532/315=树。

### 1.5 单位（机甲/载具）布置 = mission .fit [PartN]（mission.cpp createPartObject）

- 任务的 .fit（Data/Missions/<同名>.fit，FITini 文本）承载 mover 布置：
  `[PartN]` 段 `ul ObjectNumber`（→object2.pak packet 解析类）、`c TeamID`、
  `f PositionX/PositionY`（世界坐标）、`f Rotation`（度）、`b PlayerPart`、
  `l Active/l Exists`、`ul Pilot → [WarriorN]` 驾驶员档案。
- 阵营语义（单机战役）：team 0 = 玩家方，其余 team = 敌方（mission.cpp setTeamId +
  PlayerPart 强制玩家）。

## 3. 内容提取与映射（PyMC2 侧）

### 3.1 模块划分

- `src/pymc2/infrastructure/pak_parser.py`（新）：PacketFile 容器——`PakParseError`、
  `PakPacket`（index/offset/storage_type/packet_size/unpacked_size）、`PakFile`
  （`open(path)` 校验 magic/checksum、`packet_count`、`packet(i)` 枚举、
  `read_packet(i) -> bytes`（RAW 透传 / FWF 按 RAW / ZLIB 解压验证 unpackedSize /
  LZD·HF 抛 PakParseError）；`read_raw_packet(i)` 供内容层自取压缩体）。
- `src/pymc2/infrastructure/mission_pak.py`（新）：任务内容提取——
  - `TerrainGrid`：vertices_per_side + 每**tile** 高程行数组（tile 取左上顶点值，
    tiles = vertices−1）+ 世界 tile 坐标换算 `world_to_tile(x, y)`；
  - `ObjPlacement`（frozen dataclass）：obj_type_num/x/y/z/rotation_deg/damage/team_id/parent_id；
  - `MissionTerrain`：terrain + objects + `load_mission_pak(path)`（packet 0/1，其余忽略）；
  - `FitPart`（frozen dataclass）：part_index/object_number/team_id/x/y/rotation_deg/player/active；
    `load_mission_fit(path)`（[PartN] 枚举，通用 FITini 段解析器：l/f/st/ul/uc/b/c 前缀）；
  - `ObjectTypeDef`（object_class/name/appearance）+ `load_object_types(path)`
    （object2.pak 全表扫描 → dict[int, ObjectTypeDef]）。
- `src/pymc2/services/mission_pak_builder.py`（新）：`MissionPakBattle` dataclass
  （service/skipped_units/units_placed/elevation_source）+
  `build_battle_from_mission_pak(pak_path, fit_path, object_types_path, *, rng=None)`：
  - **单位布置**：.fit parts → object2.pak 类号分派——2→Mech、3→Vehicle、21→Turret、
    其余类跳过（记录）；`Active=0/Exists=0` 跳过；team 0→Faction.PLAYER、其余→ENEMY；
    id = `f"{name.lower()}-{i:02d}"`（i 为 part 序号，天然唯一）；
    武器/HP 用实体缺省（Mech ppc 25/420、Vehicle autocannon/hp80、Turret hp60）；
    MC2 `damage` 字段实测恒 0 → 忽略（§6.8）。
  - **pak packet 1 静态物**：仅类号 21（炮塔）入局（id `f"turret-{i:02d}"`，
    team<0 视为 ENEMY 守卫——炮塔必须归属一方才会交战；建筑/树/桥跳过）。
  - **高程**：packet 0 → TerrainGrid（tile 行数组）→ 40×40 **裁剪窗**（最大覆盖
    滑窗：确定性穷举全部窗位，取「入窗单位数最多 → 平局玩家方多者优先 → 西北角
    靠前」的窗；无单位时地图中心，§7.3 偏离 11）→ 窗内 min-max 线性量化
    `round((e−min)/(max−min)×3)`（max==min → 全 0）→ `ElevationGrid(rows)`。
  - **像素坐标**：MC2 128 world units/tile = PyMC2 32 px/tile（×0.25）；
    MC2 tile (row,col) → PyMC2 tile (col−c0, row−r0)，单位落 tile 中心。
  - **越界单位**：裁剪窗外（40×40 窗 vs MC2 59..119 tile 地图的固有失配）→ 跳过并
    记入 skipped_units（战报打印），不 clamp（避免堆叠）。
- `main.py`：`--mission-pak <path>`（缺省 None = 存量路径逐字节不变）——单场试玩分支：
  fit 推导 `pak.with_suffix(".fit")`、类型表推导 `pak.parent.parent/"Objects"/"object2.pak"`
  （缺失 → parts 全按 Mech 降级 + 提示，§6.9）；build → create_game 注入 → 敌方 AI →
  战斗循环（victory/defeat/QUIT）→ settlement overlay。

## 6. 偏离与裁剪清单

1. **容器实现范围**：只实现 PacketFile（任务 .pak 实际容器）；FastFile（ffile.cpp，
   .ff 资产库）不实现——任务原文猜测的 pakfile.cpp/h 不存在，已按真实源码纠正。
2. **裁剪窗（40×40）**：MC2 地图 59..119 tile/边 vs PyMC2 固定 40×40——最大覆盖滑窗
   （确定性穷举窗位，§7.3 偏离 11：实测质心窗会丢玩家单位后改为滑窗），窗外单位跳过
   （skipped_units 留痕；不做整图重采样（破坏高差语义））。
3. **高程量化**：MC2 米级 float（0..710 实测）→ ElevationGrid 0..3 int——裁剪窗内
   min-max 线性量化；[Water] 水线/[Terrain] UserMin·Max 不消费（水渲染不在本切片）。
4. **朝向不消费**：rotation 度数入 FitPart/ObjPlacement 数据结构但渲染/战斗不用
   （PyMC2 无实体旋转语义）。
5. **LZD/HF 不解压**：HF 原版即不支持；LZD（lzdecomp.cpp 旧 LZ）实测两关 0 个
   packet——Python 侧显式 PakParseError，留待后续按 lzdecomp.cpp 补。
6. **pak packet 2+（战术图/overlay/water/音效等）不解析**：只取 0（地形）+ 1（静态物）。
7. **静态物只收炮塔**：建筑/树/桥/门不布置（无建筑实体体系，远期池）；炮塔 team<0
   （中立）按 ENEMY 守卫处理（保证守卫交战语义可用）。
8. **damage/variant/squad/Pilot/CSVFile 等 .fit 字段不消费**（实测 damage 恒 0；
   PyMC2 驾驶员/武器模型独立）。
9. **object2.pak 缺失降级**：.fit parts 全按 Mech 布置 + pak 静态物全跳过 + CLI 打印
   降级提示（无类型表无法分辨类号）；不抛错阻断试玩。
10. **pak 战局不入战役链**：单场试玩（victory/defeat 即 settlement），RP/整备/salvage
    结算不走（MISSION_CHAIN 编制锁定不动，P2 偏离 §8.1 延续）。
