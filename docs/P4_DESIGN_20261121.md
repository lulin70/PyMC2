## 2. .ase 格式逆向笔记（实测 MadCat.ase，4579 行）

```
*3DSMAX_ASCIIEXPORT 200
*SCENE { *SCENE_FIRSTFRAME 0 *SCENE_LASTFRAME 100 *SCENE_FRAMESPEED 30 *SCENE_TICKSPERFRAME 160 }
*MATERIAL_LIST { *MATERIAL_COUNT 1 *MATERIAL 0 { *MATERIAL_DIFFUSE r g b *MAP_DIFFUSE { *BITMAP "\\...\MadcatRGB.tga" ... } } }
*HELPEROBJECT { *NODE_NAME "joint_root" ... }          // 骨骼/哑助手（无网格）
*GEOMOBJECT {                                           // 可渲染网格节点（实测 21 个）
    *NODE_NAME "mc_rfoot"  *NODE_PARENT "joint_rankle"
    *NODE_TM { *TM_ROW0..2 旋转矩阵  *TM_POS tx ty tz }  // 行3=平移，与 TM_POS 重复
    *MESH {
      *TIMEVALUE 0                                      // 网格导出采样点（单值，见要点 6）
      *MESH_NUMVERTEX 6  *MESH_NUMFACES 7
      *MESH_VERTEX_LIST { *MESH_VERTEX 0 x y z ... }    // **世界坐标**（实测见下）
      *MESH_FACE_LIST { *MESH_FACE 0: A:1 B:0 C:4 ... *MESH_MTLID 2 }
      *MESH_TVERTLIST { *MESH_TVERT 0 u v w }           // UV（MAX v=0 在底部）
      *MESH_TFACELIST { *MESH_TFACE 0 1 0 4 }           // 面三顶点的 tvert 索引
      *MESH_NORMALS { *MESH_FACENORMAL ... }            // 可重算，不消费
    }
}
```

实测要点：

1. **顶点已是世界坐标**：21 个节点逐一验证——每节点顶点簇围绕自身 `TM_POS`（如
   mc_rfoot TM_POS=(-12.06,-3.43,5.49)，顶点 x∈[-15.25,-9.09]），即导出时已烘焙节点
   变换，**无需重建骨骼层级**（动画场景 = 每帧预烘焙世界坐标网格序列，MC2 原版即按
   TIMEVALUE 采样播放）。静态外观渲染只需取 TIMEVALUE 0（或首个）MESH 块。
2. **坐标系**：MAX 右手系 z 轴向上。Madcat 全局包围盒 x[-20.2,20.5] y[-14,12.4]
   z[-0.01,52.8]——y+ 为机体前方（joint_*toe 脚尖朝 y+），z 为高度（52.8 单位 ≈ 蹲高）。
3. **排除项**：`Spotlight_MC` 是聚光灯体积网格（y[-95.7,-17.5] 光锥），非机体部件，
   按节点名前缀过滤；`Hit_*`/`SLCircle_*` 等为无网格助手节点。
4. **材质**：单材质 diffuse 灰 (0.4078,0.4078,0.4078) + `*BITMAP` 指向 `MadcatRGB.tga`
   （纹理贴图外观）；MESH_VERTCOL 全 0（顶点色未用）。着色取「面 UV 中心点采样纹理
   颜色 × 平面光照」即可在 32px 尺度近似贴图观感（面均 1-3px，无需逐像素 UV 采样）。
5. **规模**：MadCat.ase 21 节点 195 顶点 ~250 面——纯 Python 光栅一次 8 帧 < 1s，
   按 (机甲, 朝向) 预渲染缓存后零运行时成本。
6. **动画信息在骨骼轨迹而非逐帧网格**（实测修正）：MadcatWalk.ase / MadcatIdle.ase
   每节点只有**单个 *MESH 子块**（TIMEVALUE 4960 = 160 tick/帧 × 第 31 帧，行走周期
   定格姿态），动画由 ``*CONTROL_POS_TRACK``（5 条）/``*CONTROL_ROT_TRACK``（22 条）
   等 780 条控制器轨迹驱动，逐帧播放需骨骼层级重建 + 蒙皮——PoC 不做（任务口径：
   单静态帧足够，行走相位动画留远期池，见 §8 偏离 1/3）。

## 3. 解析器设计（src/pymc2/infrastructure/ase_parser.py，新增）

最小化原则：只解析光栅管线消费的字段（节点网格清单），不重建骨骼/动画时间轴。

- `AseParseError(Exception)`：缺 `*3DSMAX_ASCIIEXPORT` 头等结构性失败（带文件路径语义）。
- `AseFace` frozen dataclass：`a/b/c`（顶点索引）+ `mtlid`（材质槽）。
- `AseMeshNode` frozen dataclass：`name`、`vertices: tuple[(x,y,z),...]`、
  `faces: tuple[AseFace,...]`、`uvs: tuple[(u,v),...]`、`face_uvs: tuple[(i,j,k),...]`。
- `AseScene` frozen dataclass：`nodes: tuple[AseMeshNode,...]`（仅含网格节点，助手节点
  不进）、`material_diffuses: tuple[(r,g,b),...]`、`frame_count: int`（TIMEVALUE 去重数）。
- `parse_ase(path) -> AseScene`：
  - 行式解析 + 花括号深度跟踪；`*GEOMOBJECT` 块内取首个 `*MESH` 子块（TIMEVALUE 0
    优先，动画场景仅取首帧——单静态帧即满足本切片，见 §1.1）；
  - 面行解析 `A: B: C:` 与 `*MESH_MTLID`（缺 MTLID 记 0）；坏行跳过（容忍官方文件杂项）；
  - `*HELPEROBJECT` 不产节点；`*NODE_NAME` 缺失/网格空的 GEOMOBJECT 跳过。

## 4. 光栅管线设计（src/pymc2/infrastructure/mesh_render.py，新增）

软件光栅最小实现：正交投影俯视 + 固定倾角 + 绕 z 轴 8 朝向旋转 + 面深度排序填色
（平面着色）→ Surface 缓存。

- **朝向约定**（与 pygame 世界坐标对齐，x 东 y 南）：
  `HEADING_STEPS = 8`，bucket k ∈ 0..7，0=北、1=东北、…顺时针每 45°。MAX 场景 y+ 即
  机首（北），bucket k 对 mesh 绕 z 轴旋转 **−k·45°**（俯视顺时针 → 北→东→南→西）。
  量化函数 `heading_bucket(dx, dy)` 见 §6（domain 层；帧数常量与 mesh_render 的
  `HEADING_STEPS=8` 同口径）。
- **投影**：倾角 elev=45°（可调常量 `CAMERA_PITCH_DEG`）。screen_x = x；
  screen_y_up = y·sinθ + z·cosθ（世界 y 北为远、屏幕上方；pygame y 向下取负）。
- **光照**：固定方向 L=normalize(−0.35,−0.45,0.82)（顶部偏南偏西），
  shade = AMBIENT(0.35) + DIFFUSE(0.75)·max(0, n̂·L)，clamp 1.0；法线双面化
  （n̂·view_to_camera < 0 时翻转），抗官方文件面序不一致。
- **深度排序**（画师算法）：视向 d=(0, cosθ, −sinθ)，depth = p·d 大者远，降序绘制。
- **面色**：`texture` 提供时按面 UV 均值采样（v 翻转：row=(1−v)·h）；否则材质 diffuse；
  乘 shade。纹理采样单点/面（32px 下面均 1-3px，观感≈贴图，无需逐像素采样）。
- **抗缝隙**：4× 超采样画布逐面 `pygame.draw.polygon` 填充 + 同色 1px 描边封缝 →
  smoothscale 回目标尺寸（对齐官方卡 128→32 的缩放管线）。
- **画布归一**：8 帧共用同一画布尺寸（全局投影 bbox 并集），机体地面原点 (0,0) 恒映射
  画布中心 x、z=0 恒映射固定基线 y——帧间零漂移。
- **阴影**：`mech_shadow_surface(size_px)` 程序化半透明椭圆（α≈90，与选中框/血条风格
  一致），渲染层 blit 在精灵之下；帧 Surface 本体保持纯网格。
- 排除表 `EXCLUDED_NODE_PREFIXES = ("spot", "sl", "hit_")`：灯光体积/命中标记网格不入光栅。
- 入口：`render_heading_frames(scene, texture, canvas_px, *, steps=8) -> tuple[Surface,...]`
  （k=0..7 顺 bucket 序）；` MechFrameSet` 由 mc2_assets 组装（§5），mesh_render 只做纯函数。

## 5. 资产接线（mc2_assets 扩展）

- `scaled_mech_heading_sprite(chassis_kind, heading, size_px, *, damaged=False)`：
  lazy 构建（首次调用才扫 Data/TGL）→ 命中 `<stem>.ase`（大小写不敏感 stem 匹配）时
  parse + render_heading_frames（纹理 = 索引内 `stem+"rgb"` 静态卡，如 MadcatRGB.tga）
  → 8 帧按 heading 取帧 smoothscale 到 size；缓存三级：
  `_ase_frames`（stem→8 帧原生）、`_ase_scaled`（(stem,heading,size)→Surface）、
  `_ase_miss`（stem→None 负缓存，未命中零重复扫描）。
- 未命中（无 .ase 文件 / 解析失败）→ None → 渲染层回退存量静态卡路径（逐字节不变）。
- CI/无资产环境恒 None：行为保持铁律由「无 ase → 静态卡路径」保证。

## 6. 朝向状态与渲染接入

- `Mech.heading: int = 0`（bucket，纯加法）；`heading_bucket(dx, dy)` 量化函数放
  domain/entities/mech.py（渲染/服务共用常量 HEADING_STEPS 同源）。
- 更新时机：`Mech._advance_move` 按本帧移动方向更新（移动决定朝向）；
  `BattleService.tick` 单位推进后 `_update_attack_headings()`——有 attack_target 且
  无移动目标的存活机甲朝目标（MC2 原版：转向目标开火）。
- `renderer._unit_sprite`：Mech 且资产包有 ase 帧 → `scaled_mech_heading_sprite`；
  否则存量静态卡链（damaged 口径不变）。ase 帧路径 damaged 变体不生效（受损外观=
  Fall/Hit 动画态，见 §8 偏离 2）。
- ase 帧命中时 `_draw_unit` 追加半透明椭圆脚影（资产包现有静态卡路径不加——保持
  存量像素输出，回退断言稳定）。

## 8. 偏离与裁剪清单

1. **不做行走相位动画**：帧源存在（MadcatWalk.ase 等）但需逐 TIMEVALUE 采样 + ini
   Gestures 步态表联动，超出本切片 PoC 范围；静止帧（基础外观）已满足「朝向可辨」验收。
2. **ase 帧路径不接 damaged 变体**：官方受损外观 = Fall*/Hit* 动画态（V2 §1.1 结论），
   无静态受损网格（L1 实测是 LOD 而非损伤级）；damaged 口径仅在静态卡路径保留。
3. **FileName0/1 LOD 不消费**：本切片恒用近景（FileName0 对应基础 .ase）；ini 仅作
   逆向笔记不入实现。
4. **面 UV 单点采样近似贴图**：非逐像素 UV 映射——32px 呈现尺度下面均 1-3px，单点
   采样 + 平面光照观感足够；逐像素仿射贴图留远期池。
5. **炮塔/载具朝向不接入**：P4 范围限机甲（炮塔官方外观本就待 .ase 波次，见 P2 §8）。

## 9. PoC 质量结论与降级决策（回写 2026-11-21）

**结论：PoC 通过，走 .ase 光栅路线（不启用降级 A/B）。**

- 渲染性能：Madcat（21 节点 195 顶点 275 面）8 帧 128px 预渲染 **0.02s**——按
  (机甲, 朝向) 缓存后运行时零成本（缓存命中仅 dict 查找 + blit）。
- 质量闸门逐项自检（截图 `docs/assets/uat_p4/poc_madcat_8headings.png`（128px 对比
  官方静态卡）与 `poc_madcat_ingame_32px.png`（游戏内 32px 尺寸））：
  1. 轮廓合理 ✓——双足机体 + 肩部导弹舱剪影清晰，正/侧/背视图形态区分明确；
  2. 无穿面花屏 ✓——画师算法深度排序在 Madcat 网格上无可见 z-fighting/碎面；
  3. 朝向可辨 ✓——8 帧剪影两两可辨（N/S 前后对称形、E/W 窄侧面形、斜向过渡形）；
  4. 与静态卡对比：32px 游戏尺度下观感相当，且静态卡无朝向信息——本方案净增益。
- 已知瑕疵（可接受，记录）：个别面 UV 单点采样命中纹理绿色区域（脚部小面泛绿），
  32px 下不可辨；逐像素 UV 映射留远期池（§8 偏离 4）。
- 降级路线 A/B 未启用（帧源与光栅质量均达标）；若未来其他机甲 .ase 出现碎面不可修，
  按机甲粒度回退静态卡（scaled_mech_heading_sprite 未命中即自动回退，管线已内置）。
