### 1.1 关键发现：buttonlayout 是 .fit 布局定义文件，不是整版贴图

任务简报预期 `buttonlayout{640..1600}.tga` 整版 UI 图——**实测不存在 TGA**，远端实际为
5 个 FITini 布局定义文件（注意大小写混排，远端原样）：

| 远端路径 | 说明 |
| --- | --- |
| `Data/Art/buttonLayout640.fit` / `buttonLayout800.fit` / `buttonLayout1024.fit` | 低分辨率布局（大写 L） |
| `Data/Art/buttonlayout1280.fit` / `buttonlayout1600.fit` | 高分辨率布局（小写 l）——**与 1280 宽窗口匹配，本 Wave 采用** |

`buttonlayout1280.fit`（3412 行，44.7KB）：MC2 全部 in-game UI 的部件定位表——
`[Statics]` 23 个部件（ dest + 图集 UV 取块）、`[Button*]` 21 个指令按钮、
`[MechIcon*]` 16 个机甲状态图标、`[TabRects]/[Rects]` 命中区、`[ResourcePoints]/
[HelpText]` 文本槽位、`[PauseWindow]/[MissionResults]/[Objectives]` 等窗口布局。
`[HiresOffsets] xOffset=128 yOffset=256`：基础画布 1024×768，在 1280×1024 全屏下
水平居中（(1280−1024)/2=128）+ 底边锚定（y+256 → 面板贴 1024 高屏底）。

## 3. 槽位对齐设计

### 3.1 画布→屏幕偏移（renderer 模块级纯函数，可单测）

`panel_base_offset(screen_size) = ((w−1024)//2, h−768)`：对齐原版 HiresOffsets 语义
（水平居中 + 底边锚定）。1280×720 → **(128, −48)**，面板占屏 y 497..720（223px 高，
贴窗口底边），x 75..1203（画布含 ±53 补边）。

### 3.2 面板预合成（Renderer）

- `MC2AssetPack.button_layout`（lazy 缓存 property）：解析 `Data/Art/
  buttonlayout1280.fit` → 只取 `[Statics]/[ResourcePoints]/[HelpText]` → 图集按
  `FileName` 归一化（剥 `.tga` 后缀 + 小写）在 `_sprites`（Data/Art 扫描既有索引）
  精确查找 → UV 块 subsurface 裁切 → `ButtonLayout` frozen dataclass（pieces 元组 +
  画布 bbox + 三个文本槽位锚点 + dropteam stride）。
- 解析容错：零尺寸部件跳过（Static18）；FileName 未命中/UV 越界部件逐个跳过；
  fit 文件缺失/零部件解析成功 → `button_layout=None` → 渲染层完全回退现状 HUD。
- Renderer.__init__ 预合成单张 SRCALPHA surface（bbox 1128×223），每帧 1 blit @
  (75, 497)；绘制顺序：世界内容（地形/装饰/机甲/弹丸/框选）之后、文字槽位之前
  ——面板遮挡底部战场（对齐原版 UI 语义），结算遮罩仍盖在面板之上。

### 3.3 动态文本槽位（程序化 `_font`，窗口内 ASCII，中文仍走终端）

| 槽位 | 画布锚点 | 屏幕位置 | 内容 |
| --- | --- | --- | --- |
| RP | (9,746) 顶对齐 | (137,698) | `RP: <n>`（requisition_points=None 不画） |
| 任务/托管条 | compalette top (855,546) | (983,498) | `M:<mission_id>` + `AUTO: ON` + 选中 >4 时 `+N`（无内容不画） |
| dropteam 槽 i=0..3 | Static10 (227,619) + i×160 | (355+i×160, 571) | 每槽 3 行：机甲 id / `FIRE <stance>`（+GUARD 同现状）/ `HULL <p>% HEAT <n>`（+` SHUTDOWN`） |
| 提示 | HelpText (250,601) 底对齐 | (378,553) | 现有键位提示原文（show_hints 才画） |

- 选中机甲取 `service.selected_ids` 前 4 台（原版 4 dropteam 语义）；stance/热量/
  shutdown 格式化逻辑从 `_draw_hud` 抽 `_stance_text` 复用（fallback 输出不变）。
- `render()` 新增可选 kwargs `mission_id/requisition_points`（默认 None → 槽位不画，
  存量调用零改动）；`main.run_frame` 从 `Game.mission_id/Game.requisition_points`
  透传，main 任务循环每帧回写 RP（grant_rp 触发器中途入账可见）。

### 3.4 回退路径（逐字节不变）

无资产包 / 包无 fit / fit 零部件 → `_panel=None` → `render` 走现有 `_draw_hud`
（原状态行 + 原提示后缀），渲染输出与现状完全一致（e2e 全图字节比对验证）。

## 5. 偏离与裁剪清单（相对任务简报）

1. **buttonlayout 是 .fit 布局定义而非整版贴图**：简报预期下载 TGA——实测是 FITini
   定位表，面板画面拆在 MCUI_High* 图集里。改为「解析布局 + 图集 UV 取块 + 预合成」，
   观感对齐原版部件拼装。
2. **命令按钮/机甲图标/托盘/光标不下载不绘制**：[Button*]/[MechIcon*] 引用的
   MCUI_CommandButtons、MCUI_GN_MechIcons、Tray、Universal 系列图集未下载；这些按钮
   无点击交互语义（PyMC2 指令走键盘/鼠标世界交互），画非功能按钮有误导性，留后续
   Wave（接按钮需先做按钮点击命中区）。
3. **移动/攻击标记图标替换不做**：Cursors1-6a 是鼠标光标图集（屏幕空间），MC2 无
   世界空间移动标记静态图；现有程序化移动标记/攻击高亮保留，后续若确认可用图集再接。
4. **选中 >4 台**：只显示前 4 个 dropteam 槽（对齐原版 4 dropteam），超额计数并入
   任务条 `+N`。
5. **面板模式下原 HUD 状态行不再绘制**：信息拆入槽位（选中状态=palette 槽、提示=
   HelpText 槽）；无面板路径（回退）保持原状。
6. **战术地图框内部镂空**：原版为独立 tac map 渲染，PyMC2 不做该渲染，战场透出。
7. **下载范围**：6 文件入本机缓存（1 .fit + 5 TGA）；Static18 指南针因官方布局零
   尺寸实际隐藏（A_Compass_Small 仍下载留档，解析器按规则跳过）。

### 6.2 实现要点与坑

- **fixture 必须与官方段号同构**：首版合成 fit 把 dropteam palette 放在
  Static0/1、compalette top 放在 Static4——而构建函数按官方文件硬编码锚点段号
  （Static10/11 推 stride、Static8 取任务条锚点），e2e 槽位断言全空。修正为合成
  布局完整镜像官方 23 部件段号/坐标/UV（docs §2 表），与真实文件结构逐段对齐。
- **官方布局三部件会盖住断言区**：force group cover（Static20，落在 palette 0
  文字区）、右补边（Static21，落在任务条右缘）、指南针（Static18）在 fixture 中按
  零尺寸跳过处理（顺带多验一类容错），Static19/Static22 保留真实语义。
- **mypy 属性收窄**：`self._layout` 跨方法访问无法靠 render() 的判空收窄
  （union-attr ×N），`_draw_panel` 顶部局部解包 `layout, panel = self._layout,
  self._panel` 解决；`all(isinstance(...))` 生成器不收窄 → 逐键显式 isinstance。
- **panel_base_offset 复用 HiresOffsets 语义**：1280×1024 官方值 (128,256) 可由
  公式 (w−1024)//2, h−768 复现（1024−768=256），故 1280×720 → (128,−48) 与原版
  语义连续，非新发明。
- **真实资产冒烟**（/tmp 目验，不入库）：pack 34 张、layout 22 部件（官方 23−
  零尺寸 compass）、画布 bbox (−53,545)+(1128,223)、四槽位锚点与官方表一致；
  品红覆盖探测证实镂空区（tac map 内部/画布外）透出战场。截图
  `/tmp/v3_real_assets_smoke.png` 由用户真机复核（真实 MC2 艺术像素零入库）。
