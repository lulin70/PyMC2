## Executive Summary

**单点接入 + 双模式分支**架构：新建纯函数投影模块（projection.py），Renderer 以构造参数 `projection` 切换 top/isometric，主循环点击拾取经 Renderer 单一逆变换入口恢复世界坐标。**核心设计决策：投影仅渲染层，逻辑层世界坐标不变**——命中/LOS/移动/热量全链路零改动（消解差距分析 §5.1 技术挑战 3）。

核心接地结论（P3 前置核对完成）：
- `Renderer.world_to_screen`（renderer.py L477）已是**唯一投影入口**，全部实体绘制（单位/装饰/标记/弹丸/框选）都经它 → 单点改造即可覆盖 FR-2.1
- 高程偏移已在绘制侧统一走 `_elev_offset(tile)`（L486-488），丘陵地形表面预构建时烘焙同行偏移（L308 `shift = e * ELEVATION_STEP_PX`）→ 两侧偏移天然一致，整面缩放方案成立
- 点击拾取唯一入口 `main._world_pos`（main.py L226）→ 逆变换单点改造
- HUD/面板绘制不经过 world_to_screen（屏幕空间直绘）→ FR-5 零改动达成

## §2 投影数学（presentation/projection.py，新建）

```python
PROJECTION_TOP = "top"
PROJECTION_ISO = "isometric"

ISO_TILT_DEG = 30.0                       # 固定倾角（MVP，差距分析 §5.1 缓解项定值）
ISO_Y_SCALE = math.cos(math.radians(ISO_TILT_DEG))  # ≈ 0.8660 纵向压缩系数

def world_to_screen_iso(x, y, cam_x, cam_y) -> tuple[int, int]:
    """screen_x = x - cam_x；screen_y = (y - cam_y) × ISO_Y_SCALE（高程项由调用侧叠加）"""
    return (int(x - cam_x), int((y - cam_y) * ISO_Y_SCALE))

def screen_to_world_iso(sx, sy, cam_x, cam_y) -> tuple[float, float]:
    """逆变换（平坦地形精确；高程项由 Renderer 两段式修正，见 §4）"""
    return (sx + cam_x, sy / ISO_Y_SCALE + cam_y)
```

**常量定值依据**（对照 MC2 截图，M2 里程碑预演校准点）：
- 30° 倾角 → 纵向压缩 = cos(30°) ≈ 0.866（差距分析 §5.1 缓解项「固定倾斜角 30°」；28-60° FOV 连续可调与透视缩放属远期 Out of Scope）
- 高程台阶屏幕偏移：`level × ELEVATION_STEP_PX × ISO_Y_SCALE`（压缩比例保持观感一致，见 §3）

## §3 Renderer 接入（presentation/renderer.py 修改）

```python
def __init__(self, screen, asset_pack=None, elevation=None, ..., projection: str = PROJECTION_TOP):
    self._iso = projection == PROJECTION_ISO
    # 地形表面：isometric 下整面纵向缩放（smoothscale 一次，缓存复用，NFR 性能）。
    # 丘陵 terrace 烘焙偏移随整面缩放同比压缩 → 与实体 _elev_offset 压缩系数一致。
    if self._iso:
        base, offset = self._build_terrain()
        self._terrain = pygame.transform.smoothscale(
            base, (MAP_SIZE_PX, round(MAP_SIZE_PX * ISO_Y_SCALE)))
        self._terrain_y_offset = round(offset * ISO_Y_SCALE)
    else:
        self._terrain, self._terrain_y_offset = self._build_terrain()  # 存量路径零改动
```

**双模式分支点（全部集中于 Renderer，调用侧零改动）**：

| 方法 | top（存量） | isometric（新增分支） |
|------|------------|----------------------|
| `world_to_screen(x, y, cam_x, cam_y)` L477 | `int(x-cam_x), int(y-cam_y)` | `projection.world_to_screen_iso(...)` |
| `_elev_offset(tile)` L486 | `level × ELEVATION_STEP_PX` | `level × ELEVATION_STEP_PX × ISO_Y_SCALE` |
| `screen_to_world(sx, sy, cam_x, cam_y)` 新增 | `(sx+cam_x, sy+cam_y)`（= 存量 `_world_pos` 恒等） | 两段式修正（§4） |
| `terrain_screen_height()` 新增 | `MAP_SIZE_PX + _terrain_y_offset` | `round(MAP_SIZE_PX×ISO_Y_SCALE) + _terrain_y_offset` |

**一致性推导**（绘制正确性关键）：实体屏幕 y = `(y−cam_y)×ISO_Y_SCALE − elev(tile)×STEP×ISO_Y_SCALE`；地形表面烘焙像素 y = `y×ISO_Y_SCALE − cam_y×ISO_Y_SCALE − baked_elev×STEP×ISO_Y_SCALE`。两式逐项相等 → 单位踩在地形表面像素上，丘陵 tile 同样对齐。

**遮挡排序**：`(elevation, y)` 排序键语义不变（L526），axis-aligned 仿射保序（y 单调压缩）→ 存量遮挡次序在 isometric 下仍正确（FR-2.3）。

**框选矩形**：世界矩形四角经仿射仍为轴对齐矩形 → `_draw_drag_rect` 零改动。

**HUD/面板**：绘制不经过 world_to_screen → FR-5.2 天然达成（像素 diff = 0 由 E2E 断言）。

## §4 点击拾取逆变换（renderer.screen_to_world + main._world_pos）

```python
# renderer.py 新增方法
def screen_to_world(self, sx, sy, cam_x, cam_y) -> tuple[float, float]:
    if not self._iso:
        return (sx + cam_x, sy + cam_y)            # 存量恒等路径
    wx, wy = screen_to_world_iso(sx, sy, cam_x, cam_y)   # 一段：忽略高程的近似
    # 二段：用近似 tile 的高程回补（一次查表，不迭代）：
    # sy = (wy−cam_y)×K − e×STEP×K  →  wy = sy/K + cam_y + e×STEP
    e = self._tile_elevation(self._tile_of_px(wx, wy))
    return (wx, wy + e * ELEVATION_STEP_PX)

# main.py 修改（L226，唯一入口委托）
def _world_pos(game, screen_pos):
    return game.renderer.screen_to_world(*screen_pos, game.camera.x, game.camera.y)
```

**误差分析**（FR-3.1 ≤1 tile 验收依据）：一段近似逆变换误差 = `e×STEP×K` 像素（e=ELEVATION_MAX 时 ≈ 48×0.866 ≈ 42px ≈ 1.3 tile，超差）→ 二段回补后，目标 tile 自身高程精确抵消；仅 tile 边界处因近似 tile 判定可能落到邻 tile，误差 < 1 tile（TILE_SIZE_PX=32）。**不迭代、无整网搜索**——一次查表 O(1)。

**相机钳制**（main.update_camera L231）：`max_y` 由 `MAP_SIZE_PX − height` 改为 `renderer.terrain_screen_height() − height`（top 模式该值 = 存量 `MAP_SIZE_PX + 0 − height`，恒等）；`max_x` 不变（x 无压缩）。
