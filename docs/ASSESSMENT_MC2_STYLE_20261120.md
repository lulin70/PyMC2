# 评估：地形与机甲「MC2 方式」完整实现的工作量

- 日期：2026-11-20
- 性质：工作量评估（讨论用，未立项）
- 依据：docs/V2_DESIGN_20261119.md §1（远端资产勘测）、docs/V3_DESIGN_20261120.md §2（buttonlayout/MCUI 探测）、MC2 Shared Source 仓库结构

## 1. 现状（V1-V3 已交付）与 MC2 原版的差距

| 模块 | PyMC2 现状 | MC2 原版 |
| --- | --- | --- |
| 地形纹理 | 官方 Detail/道路贴图铺底 + 装饰撒点（V1） | 任务 .pak 包内逐 tile 贴图分配 + overlay |
| 地形高程 | **无**（纯平面 40×40） | 高度图 terrace 渲染（侧面/阴影），高度联动移动与视线 |
| 机甲 | 每机甲一张静态卡 TGA + 受损变体回退（V2） | .ase 场景（网格+动画帧）实时渲染：8/16 朝向 × 行走相位 × 损伤/死亡帧 |
| UI | 官方布局解析 + 槽位对齐（V3） | 同（已对齐） |

## 3. 主要风险

1. **观感逼近**：.ase 网格自渲染无原版光照/调色板管线，观感可能「形似神不似」——需先用单机甲（Madcat）做 PoC 验收再铺开；
2. **.pak 逆向**：Shared Source 有读取代码可对照，但格式细节多，解析范围容易膨胀（只取本项目需要的 terrain/tile/object 三类）；
3. **帧量**：全量帧集大，必须预渲染+缓存（运行时只 blit）。

## 4. 中间态选项（性价比路线，6-9 天 / 3-4 波）

不追求完整复刻，取观感收益最大的 80%：

1. **机甲 8 朝向静态帧**（不含行走相位，转向时切帧）：.ase 解析 + 8 帧/台预渲染 + 朝向切换 ≈ 3-5 天；
2. **地形视觉 terrace**（只做高度偏移+侧面渲染，不联动玩法；高度图先用程序化生成或手写小地图）≈ 3-4 天。

## 5. 建议

- 若目标是「画面像 MC2」：走中间态路线（3-4 波），收益/成本比最高；
- 若目标是「机制也像 MC2」（高程视线/移动）：须走完整路线（6-8 波），且建议排在高程联动玩法单独验收；
- 两条路线都以 Madcat 单机甲 PoC 起步，观感确认后再铺开到 Thor/UrbanMech/Jagermech。
