## Executive Summary

四层架构：**数据模型（loadout.py）→ 校验/IO 服务（loadout_service.py）→ GUI 状态机（mech_lab.py）→ 战斗接入（mech.py 扩展 + battle_service 开火路径多武器化）**。

核心接地结论（P3 前置核对完成）：
- `MechChassis.slots: dict[MechLocation, list[Weapon]]` **多武器槽结构已存在**（mech_chassis.py L129），W2 仅需战斗层消费它
- `Weapon.cooldown_s/cd_remaining` 独立 CD 机制按实例生效（2.1 核销路径：每 Weapon 一个实例）
- 底盘吨位：PRD §5.1 定标 20-100 吨（madcat=75t 样例）；PyMC2 底盘按 hull 缩放（`from_total`），吨位映射按 hull 分档
- 战斗层开火只用 `mech.weapon` 单字段（battle_service.py L274/L287/L434）→ 多槽位开火需最小扩展

## §1 分层架构

```
presentation/mech_lab.py        # GUI：屏幕状态机 + 拖拽（只读模型，经 service 变更）
        ↓ 调用
services/loadout_service.py     # 校验 + 保存/载入 + apply（无 pygame 依赖）
        ↓ 操作
domain/loadout.py               # LoadoutConfig/WeaponCatalog/吨位表（纯数据，零依赖）
        ↓ 应用
domain/entities/mech.py         # Mech.weapons 扩展 + battle_service 开火路径
```

**依赖方向约束**：GUI → service → domain，禁止反向；domain 层不 import pygame（可测试性 NFR）。

## §2 数据模型 API（domain/loadout.py，新建）

```python
class MechLocation(str, Enum)  # 复用 mech_chassis.MechLocation（8 部位：H/CT/LT/RT/LA/RA/LL/RL）

@dataclass(frozen=True)
class WeaponSpec:
    """武器目录条目（静态表，来自 PRD §5.2）。"""
    name: str          # "PPC"
    weapon_type: str   # "BALLISTIC"|"ENERGY"|"MISSILE"（WeaponType.value）
    damage: int
    range_px: float
    cooldown_s: float
    heat_per_shot: float
    tonnage: float     # 装备吨位（W2 新增字段，目录定标）

WEAPON_LIBRARY: tuple[WeaponSpec, ...]  # 目录（≥6 条：Standard/PPC/LRM-20/AC-10/Small Laser/Flamer）

@dataclass
class WeaponSlotConfig:
    spec_name: str           # WEAPON_LIBRARY.name 外键
    location: MechLocation   # 挂载部位

@dataclass
class LoadoutConfig:
    chassis_kind: str                  # "medium"|"heavy"（hull 分档键）
    armor_allocation: dict[str, int]   # 8 部位装甲点数（总点数受底盘上限约束）
    weapons: list[WeaponSlotConfig]    # 多槽位（顺序即槽位序）

    def total_tonnage(self) -> float            # 底盘基准 + Σ装甲换算 + Σ武器吨位
    def validate(self) -> LoadoutError | None   # None=合法；错误对象见 §3
    def to_json(self) -> dict                   # 序列化（schema_version 字段）
    @classmethod
    def from_json(cls, data: dict) -> LoadoutConfig
    def apply(self, mech: Mech) -> None         # 装甲覆盖 + 重建 chassis.slots（见 §5）
```

### 吨位表（底盘分档，hull → tonnage_max 映射）

| 分档 | hull（总余量） | tonnage_max | PRD 依据 |
|------|---------------|-------------|----------|
| light | ≤120 | 35t | PRD §4.1 轻型 20-35t |
| medium | 121-180 | 55t | 中型 40-55t |
| heavy | 181-240 | 75t | 重型 60-75t（madcat 样例 75t） |
| assault | >240 | 100t | 突击 80-100t |

装甲换算：1 装甲点 = 0.5t（MC2 常规口径简化，P8 实现时落注释）；底盘基准吨位 = 分档下限（medium=40t）。

## §3 校验契约（services/loadout_service.py）

```python
@dataclass(frozen=True)
class LoadoutError:
    code: str        # "OVERWEIGHT"|"UNKNOWN_WEAPON"|"BAD_LOCATION"|"ARMOR_CAP"|"BAD_JSON"|"FILE_ERROR"
    message: str
    detail: dict     # overweight 时：{"total": 61.5, "max": 55.0}

class LoadoutService:
    def validate(config) -> LoadoutError | None
    def save(config, name: str) -> LoadoutError | None    # 白名单 [A-Za-z0-9_-]，≤1MB，路径 ~/.pymc2/loadouts/
    def load(name: str) -> LoadoutConfig | LoadoutError   # 3 类损坏用例全覆盖
    def list_saved() -> list[str]
    def default_config(chassis_kind: str) -> LoadoutConfig  # 底盘工厂对齐（零破坏默认路径）
```

**验收映射**：FR-2.2（错误对象非 raise）、FR-3.1（白名单+大小限制）、FR-3.3（BAD_JSON 不崩溃）。

### 4.2 拖拽状态机（FR-4.3）

```
IDLE ──mousedown(武器库条目)──→ DRAGGING
DRAGGING ──mouseup(槽位矩形命中)──→ 尝试装入：validate 单步（吨位/部位合法性）
    ├─ 合法 → config 更新，重量条刷新（同帧）→ IDLE
    └─ 非法 → error_line 红显 2s → IDLE（配置不变）
DRAGGING ──mouseup(非槽位)──→ IDLE（无变更）
槽位已有武器 + mousedown(槽位) ──→ DRAGGING(卸下)  # US-4
```

## §5 战斗接入（mech.py + battle_service.py 最小扩展）

### 5.1 Mech.weapons 扩展

```python
@property
def weapons(self) -> tuple[Weapon, ...]:
    """全部挂载武器（chassis.slots 展平）；单武器存量路径语义不变。"""
    return tuple(w for slot in self.chassis.slots.values() for w in slot)
```

`mech.weapon` 保留（主武器 = 首槽位武器，存量读路径零改动）。

### 5.2 开火路径多武器化（battle_service）

```python
# fire_at / 自动交火：attacker.weapon → attacker.weapons 中首个 ready 且射程覆盖的武器
weapon = next((w for w in attacker.weapons if w.ready and w.range_px >= distance), None)
if weapon is None:
    return False
# 后续弹道构造/CD 写入/热量均用 weapon（每实例独立 CD → FR-5.3 自动满足）
```

**存量兼容证明**：单武器机甲 `weapons` 恒等于 `(weapon,)` → 选择器恒返回同一实例 → 行为逐字节一致（592 回归钉）。

### 5.3 LoadoutConfig.apply(mech)

1. 装甲覆盖：`chassis.parts[loc].armor = allocation[loc]`（structure 不动）
2. 清空 `chassis.slots`，按 weapons 序 `mount_weapon(Weapon(spec...)）`
3. `mech.max_hull` 重算 = total_integrity
4. 出击路径：`create_game` 前 `LoadoutService.load(name)` 成功 → apply；无配置/损坏 → 底盘工厂默认（FR-5.1 零破坏）
