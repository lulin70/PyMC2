## 1. 视线判定（src/pymc2/domain/elevation.py，ElevationGrid 新方法）

`has_line_of_sight(from_tile, to_tile) -> bool`：射手 tile → 目标 tile 视线是否通。

- **遮挡模型**（简化 MC2 语义，记录于本节）：单位眼高 1 级（`EYE_HEIGHT_LEVELS = 1`）
  ——视线高度在两端点间线性插值：起点 = 射手 tile 高程 + 1，终点 = 目标 tile 高程 + 1；
  途经 tile 高程 ≥ 该处插值视线高度 → 遮挡。
- **途经 tile 遍历**：Bresenham 整数直线（含斜向步），不含两端点——射手/目标所在 tile
  自身高程不参与遮挡（端点不算遮挡）；总步数 n = max(|dx|,|dy|)，第 i 步（i=1..n-1）
  的插值比例 t = i/n。
- **边界**：n ≤ 1（同格/相邻）无途经 tile → 恒通；地图外途经 tile 高程按 0 参与插值
  （P1-A「越界视为 0」同口径，平面延伸不遮挡）。
- **is_flat() 快路径**：全零平面直接判通（O(1)）——flat 下所有调用点行为与存量
  逐字节一致，这是「默认 flat 511 存量测试零语义改动」的机制保证。

## 2. 交战联动（src/pymc2/services/battle_service.py）

MC2 语义：无视线不开火。联动三个点，全部收敛到 `ElevationGrid.has_line_of_sight`
（service 经 `self.elevation` 调用，flat 快路径下全部为真 → 零改动）：

1. **获取（候选筛选）**：`_nearest_enemy_in_range`（自动交战重锁入口）增加 LOS 过滤
   ——射程内但视线被挡的敌机甲不作为锁定候选；`nearest_enemy`（AI 指挥官接近/
   standoff 用，见 §5.4）**不加** LOS 过滤（向被挡敌机甲接近直到通视是期望行为）。
2. **击发（全路径咽喉）**：`fire_at` 在射程校验后增加 LOS 复验——被挡 → 返回 False，
   不结算弹丸/不产热/不记技能/不写冷却。该咽喉同时覆盖：
   - 玩家/指挥官显式 `ATTACK_OBJECT`：`_dispatch_attack` 中 `fire_at` 失败 → 锁定不落
     （`attack_target_id` 不写）——按现有指令失败惯例：指令仍入 `order_log`、
     `dispatch` 返回 False；AI 指挥官下轮决策重发即「延迟到视线恢复」，零新增状态。
   - `_auto_engage` 自动锁定击发。
3. **防指令日志刷屏**：`_auto_engage` 下发条件（现：weapon ready/可用/非关机）追加
   LOS 判定——已锁定目标被挡时不下发 SELF 源指令（沿用「冷却/关机期间不下发」
   同款惯例）；flat 下该判定恒真，下发时序与存量一致。

**锁定保持语义**：已锁定目标被挡 ≠ 锁定失效——锁定有效性仍按存量口径（存活+射程），
被挡期间仅抑制击发（§2.2/§2.3）；视线恢复后若冷却已过立即开火。获取侧 LOS 过滤
只作用于「新锁定」候选（§2.1）。理由：MC2 中指定目标后失去视线不换目标；若按
「被挡即清锁重锁」则被挡瞬间会跳打其他可见敌（战术语义漂移）且锁定抖动。

**冷却决策（择一记录）**：**冷却照常走**——被挡 tick 未击发 → 不写 `cd_remaining`
（弹未出膛不消耗冷却）；冷却计时本身每 tick 照常推进（`Mech.tick` → `weapon.tick`，
不动）。理由：与让路「武器/散热照常推进」同款语义（被阻不冻结战斗侧计时），且
视线恢复后若冷却已走完立即开火，不引入人为迟滞；「被挡也走一整轮冷却」需新增
状态机，收益不成立。

**弹丸飞行**：击发瞬间判定后弹丸按直线飞至弹着点，飞行途中不复验地形/视线
（MC2 同款简化：地形静态，击发瞬间已通视即必达）。

**零改动清单**：让路协商（占位/互换与高程解耦）、热量、部位伤害结算、技能记账、
移动爬升校验/步进耗时（P1-A 交付语义）全部原样。

## 3. 渲染提示（可选交付，最小实现）

## 5. 偏离与裁剪

1. **简化遮挡模型**：线性插值 + 眼高 1 级 + 单点采样（途经 tile 高程 ≥ 插值视线高度
   即挡）；MC2 原版按单位实际高度/地形类型计算遮挡弧，此处不引入单位体型与
   地形分类——战术效果（山体隔断直射、高点俯射越障）保留，精度让位可测性。
2. **插值采样比例取 Bresenham 步进序**（t = i/n）：整数步进比例而非欧氏弧长比例，
   确定性可断言；与整数 Bresenham 同源，无浮点路径歧义。
3. **锁定不因遮挡清除**（§2 锁定保持语义）：被挡期间 `attack_target_id` 保持、
   `_engagement_target` 有效性口径不变——与「击发前复验」条款一致，防锁定抖动。
4. **`nearest_enemy` 不过滤 LOS**：AI 指挥官接近语义依赖它（被挡目标需先接近）；
   LOS 过滤只落在「锁定候选」`_nearest_enemy_in_range` 与击发咽喉 `fire_at`。
5. **显式指令被挡 = 失败惯例**（指令入账、dispatch False、锁不落），不新增
   REJECT 条目类型、不入新队列（「延迟到视线恢复」由 AI/玩家重发实现）。
6. **NO LOS 仅回退 HUD 状态行**：V3 面板槽位不画（布局不动）、无世界空间标记
   （攻击高亮语义不变）——可选项取最小可观测实现。
7. **e2e 构图用手写高程行数组**：不用 `generate_hills`（seed 地形难以保证
   「射手-山体-目标」三点几何稳定），显式 rows 网格让切片布局确定性可断言；
   `generate_hills` 场景以真实验证留待人工 UAT。
