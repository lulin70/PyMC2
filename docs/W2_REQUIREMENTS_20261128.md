## 1. 问题陈述

PyMC2 机甲配置当前硬编码（底盘工厂直接构造 Mech），玩家无法在出击前定制武器/装甲配载。这与 MC2 核心循环（装配 → 出击 → 战利品 → 再装配）冲突，且阻塞：

- **2.1 残留项**：多武器多槽位独立 CD（Weapon.cooldown_s 机制已有，缺多槽位展开）
- **Phase 1 E2E 切片**（W1-W2 后）：「装配界面改配置 → 出击」是必经路径，W2 不交付则 Phase 1 无法执行
- **W4 存档/读档（2.27）**：存档需序列化装配配置，配置模型先行是前置

## 2. 范围

### In Scope
1. 装配配置数据模型（底盘 + 部位装甲 + 多武器槽 + 重量预算）
2. 重量校验与超重拦截
3. 配置保存/载入（JSON 文件，本地用户目录）
4. GUI 装配界面（拖拽武器/装甲到槽位，pygame 实现）
5. 装配结果接入战斗（BattleService 出击使用玩家配置）

### Out of Scope（远期池/后续波）
- 装甲类型差异（W4+：反应装甲等，W2 只做吨位分配）
- 战役经济耦合（RefitService 修理/雇用已存在，W2 不改动其经济规则）
- 官方 CBILL/零件系统（远期池）
- 多人配置同步（N/A 单机）

|---|------|----------|

## 4. 功能需求与可量化验收标准（Exit Gate 核心）

### FR-1 装配配置数据模型
- **FR-1.1**: `LoadoutConfig` 数据类包含：chassis_kind、部位装甲分配（头/左躯干/右躯干/左臂/右臂/左腿/右腿，7 部位）、武器槽列表（每槽：部位 + 武器类型）
- **FR-1.2**: 验收 — 模型可 JSON 序列化/反序列化，roundtrip 后逐字段相等（`config == LoadoutConfig.from_json(config.to_json())` 恒真）
- **FR-1.3**: 验收 — `LoadoutConfig.apply(mech)` 后 Mech 部位装甲值与武器槽与配置一致（单元测试断言 7 部位 + 槽位数）

### FR-2 重量校验与超重拦截
- **FR-2.1**: 每底盘有 `tonnage_max`（取自 MC2 设计底盘表）；`LoadoutConfig.total_tonnage()` 汇总底盘 + 装甲 + 武器吨位
- **FR-2.2**: 验收 — 超重配置调用确认时返回拒绝（`validate() → OverweightError|Ok`），拒绝路径零异常泄漏（返回值/错误对象，非 raise 中断 GUI）
- **FR-2.3**: 验收 — GUI 超重时「确认」按钮禁用 + 红色提示行；重量条实时刷新（添加/移除 ≤1 帧延迟）

### FR-3 配置保存/载入
- **FR-3.1**: 保存路径 `~/.pymc2/loadouts/{name}.json`；文件名安全过滤（`[A-Za-z0-9_-]`，防路径注入）
- **FR-3.2**: 验收 — 保存 → 新进程载入 → 配置逐字段一致（roundtrip 集成测试）
- **FR-3.3**: 验收 — 损坏 JSON 载入返回错误提示不崩溃（枚举 ≥3 种损坏用例：截断/空文件/字段类型错）

### FR-4 GUI 装配界面
- **FR-4.1**: 进入方式：主界面按键（建议 `L` = Mech Lab）进入/退出；退出返回主界面且战局状态不变
- **FR-4.2**: 布局：左侧武器库列表（可滚动）、中央机甲部位图（7 部位槽位）、右侧配载摘要（吨位条 + 部位装甲值）
- **FR-4.3**: 交互：鼠标拖拽武器库条目 → 释放到槽位（命中检测 ≤槽位矩形）；拖拽中显示幽灵图标跟随光标
- **FR-4.4**: 验收 — E2E 截图 3 张存 `docs/assets/uat_w2/`：初始界面、拖拽中、超重红显

### FR-5 战斗接入
- **FR-5.1**: `create_game` / BattleService 出击时优先读玩家 LoadoutConfig（存在则应用，无则底盘工厂默认，零破坏）
- **FR-5.2**: 验收 — 应用 PPC 配置的机甲开火弹道类型为 PPC（弹道/能量分派正确）
- **FR-5.3**: 验收 — 多武器机甲各槽独立 CD 生效（2.1 残留核销：同帧连开 2 槽 → 两 CD 独立递减）

### FR-6 兼容性硬约束
- **FR-6.1**: 存量 592 passed 零语义改动（flat 模式渲染逐字节一致回归钉）
- **FR-6.2**: MC2 资产只读（`~/.pymc2/mc2-assets` 不写入）；loadouts 目录独立于资产目录
- **FR-6.3**: 无资产环境（asset_pack=None）下装配界面仍可用（纯程序化绘制，无 TGA 依赖）

## 5. 非功能需求

| NFR | 目标 |
|-----|------|
| 性能 | 装配界面 60 FPS（拖拽重绘 ≤16ms/帧）；重量计算 O(槽位数) 无感知延迟 |
| 可靠性 | 配置文件 IO 全路径错误处理，任何损坏输入不崩溃（FR-3.3） |
| 可测试性 | 数据模型/校验/IO 与 GUI 分层，模型层覆盖率 ≥80% |
| 安全 | 文件名白名单过滤（路径穿越防护）；JSON 解析限制文件大小 ≤1MB |

## 6. 依赖与风险

| 项 | 类型 | 说明 |
|----|------|------|
| Weapon/Mech 数据模型 | 已有 | Weapon.cooldown_s + Mech 部位结构直接复用 |
| RefitService | 已有 | 仅相邻不改；装配入口挂主界面菜单 |
| 底盘吨位表 | **数据缺口** | MC2 设计文档底盘吨位需核对（P3 前确认，缺则按武器库总吨位定标） |
| pygame 拖拽 | 技术 | 无现成组件，需自实现命中检测 + 拖拽状态机（P3 评估，预估 1.5 人天） |
| 8 人天预算 | 排期 | FR-1/2/3（模型+校验+IO）≈3 天，FR-4 GUI ≈3.5 天，FR-5 接入+回归 ≈1.5 天 |
