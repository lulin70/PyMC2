## 1. 产品概述

### 1.1 产品定位
MechCommander 2 是一款实时战术策略游戏（RTS），玩家指挥由 4-12 台巨型机甲（BattleMech）组成的小队，在 3D 地形上执行战术任务。核心玩法融合：
- **实时战术微操**：非回合制，同时控制多单位
- **资源管理**：热量/弹药/护甲的即时决策
- **地形战术**：高程视线遮挡、移动代价、掩体利用
- **机甲装配**：任务前自定义武器/装甲配置

### 1.2 核心特性
1. **固定斜视角 3D 渲染**：28-60° FOV 透视投影，单位为精灵（2.5D）
2. **数据驱动内容**：.fit 配置 + .pak 资源包 + ABL 脚本任务逻辑
3. **模块化机甲系统**：底盘/武器/引擎可自由组合
4. **动态地形**：20×20 顶点块高程网格，实时光照与阴影

## 2. 功能需求

### 2.1 核心玩法循环

#### 2.1.1 战前准备阶段
| 功能 | 描述 | 优先级 |
|------|------|--------|
| 机甲选择 | 从可用名册中选择 4-12 台机甲 | P0 |
| 装配编辑器 | 修改武器/护甲/引擎/弹药配置 | P0 |
| 驾驶员分配 | 为每台机甲指派驾驶员（技能影响命中率） | P1 |
| 任务简报 | 展示目标、地图预览、敌军情报 | P1 |

**验收标准**：
- 装配界面展示重量/临界槽位实时校验
- 非法配置（超重/引擎不兼容）阻止出击
- 驾驶员技能差异在战斗中产生 ±15% 命中率变化

#### 2.1.2 战斗执行阶段
| 功能 | 描述 | 优先级 |
|------|------|--------|
| 实时单位控制 | 右键移动、左键选择、热键切换 | P0 |
| 武器射击 | 自动开火或手动指定目标 | P0 |
| 热量管理 | 武器开火产生热量，超阈值关机 | P0 |
| 视线判定 | 高地形遮挡低目标，显示 NO LOS 提示 | P1 |
| 战术地图 | 迷你地图显示敌我单位、目标点 | P1 |
| 暂停指令 | 空格暂停发布多单位命令 | P2 |

**验收标准**：
- 单位响应延迟 <100ms（从点击到路径寻找开始）
- 视线遮挡判定与地形高程严格一致
- 热量达 100% 时单位强��关机 10 秒

#### 2.1.3 战后结算阶段
| 功能 | 描述 | 优先级 |
|------|------|--------|
| 目标完成统计 | 主目标/次要目标/奖励目标独立计分 | P0 |
| 伤害统计 | 展示每台机甲受损部位与剩余护甲 | P1 |
| 战利品获取 | 击毁敌军后回收零件/武器 | P1 |
| 晋升系统 | 驾驶员获得经验值提升技能等级 | P2 |

### 2.2 地形系统需求

#### 2.2.1 高程网格
- **网格规格**：40×40 至 120×120 顶点（对应 59-119 tile）
- **高程范围**：0-255 级（每级 128 world units）
- **渲染方式**：顶点上移 + 分级提亮 + 北缘脚线 + 崖壁侧面

#### 2.2.2 地形类型
| 类型 | 移动代价 | 视觉特征 |
|------|----------|----------|
| 草地 | 1.0× | 绿色纹理 + 植被撒点 |
| 泥地 | 1.2× | 棕色纹理 + 泥泞效果 |
| 岩石 | 1.5× | 灰色纹理 + 碎石 |
| 道路 | 0.8× | 铺装纹理（无移动惩罚） |
| 水域 | 2.0× | 蓝色透明 + 波浪动画 |
| 森林 | 1.3× | 树木遮挡视线 |

#### 2.2.3 光照与阴影
- **光源**：单向平行光（方向可配置）
- **顶点法线**：8 邻域三角形平均
- **实时阴影**：光线投射采样地形，标记遮挡顶点
- **更新触发**：地形破坏（爆炸）时局部重算

### 2.3 机甲系统需求

#### 2.3.1 底盘属性
| 属性 | 范围 | 说明 |
|------|------|------|
| 吨位 | 20-100 吨 | 决定总装备重量上限 |
| 护甲点数 | 50-400 | 分配到 8 个部位（头/躯干/四肢） |
| 临界槽位 | 12-30 | 武器/弹药/设备占用槽位 |
| 最大速度 | 30-100 km/h | 引擎评级 / 吨位 |

#### 2.3.2 武器系统
| 武器类型 | 伤害特性 | 热量 | 弹药 |
|----------|----------|------|------|
| BALLISTIC | 实弹快速命中 | 低 | 有限（AC/5-20 需弹药） |
| ENERGY | 激光无视护甲加成 | 高 | 无限 |
| MISSILE | 齐射散布 + 末端加速 | 中 | 有限（LRM/SRM） |

**武器属性表**（示例）：
- **AC/20**：伤害 20，射程 270px，热量 7，弹速 1.5×
- **Large Laser**：伤害 8，射程 450px，热量 8，弹速 1.0×
- **LRM-20**：伤害 20（分 3 发），射程 630px，热量 6，弹速 0.7×

#### 2.3.3 命中判定
```
命中率 = 基础命中率 × (1 - 距离衰减 × 距离/射程) × 技能系数 × 热量精度系数
```
- **基础命中率**：100%（贴脸）→ 25%（射程边缘）
- **技能系数**：0.85 + 0.06 × 驾驶员等级（钳制在 0.7-1.2）
- **热量惩罚**：热量 >50% 时，每增加 10% 降低 5% 命中率

#### 2.3.4 伤害分配
1. **命中判定**：投骰子 < 命中率 → 命中，否则散布在目标周围 8-48px 半径
2. **部位判定**（命中时）：
   - 中躯干（CT）：30%
   - 左/右躯干（LT/RT）：各 15%
   - 左/右臂（LA/RA）：各 10%
   - 左/右腿（LL/RL）：各 10%
   - 头部（H）：5%
3. **伤害结算**：
   - 护甲吸收 → 护甲归零后伤害溢出到内部结构
   - CT 内部结构归零 → 机甲击毁
   - 其他部位归零 → 部位瘫痪（武器/移动失效）

### 2.4 任务系统需求

#### 2.4.1 目标类型
| 类型 | 描述 | 失败条件 |
|------|------|----------|
| PrimaryGoal | 主要目标（必须完成） | 玩家全灭 / 超时 |
| SecondaryGoal | 次要目标（加分项） | 无 |
| BonusGoal | 奖励目标（隐藏挑战） | 无 |

#### 2.4.2 任务脚本（ABL）
- **触发器**：时间 / 单位进入区域 / 敌军数量阈值
- **动作**：生成增援 / 更新目标 / 播放过场动画
- **条件判断**：IF/ELSE 逻辑，支持全局变量

**示例脚本伪代码**：
```abl
IF (playerUnitsInZone(objectiveArea) AND enemyCount < 3) THEN
    setObjectiveStatus("obj_01", Success);
    spawnReinforcements("convoy_02", position(100, 200));
END
```

#### 2.4.3 任务包格式（.pak）
- **容器结构**：索引表 + 多个压缩数据包
- **包内容**：地形高度图 / 对象列表 / 纹理资源 / 任务脚本
- **压缩算法**：LZ（70% 压缩率）或 zLib

### 2.5 UI 需求

#### 2.5.1 HUD 布局（1280×768 分辨率）
| 元素 | 位置 | 功能 |
|------|------|------|
| 机甲图标栏 | 底部左侧（229-304px 宽） | 显示 16 台机甲状态（血条/驾驶员头像） |
| 命令按钮 | 底部右侧（885-1015px 宽） | Jump/Run/Stop/Guard 等 9 个按钮 |
| 战术地图 | 左下角（211×206px） | 实时敌我单位位置 |
| 信息窗口 | 右上角（208×208px） | 选中单位详情（护甲图/武器列表） |
| 目标列表 | 顶部（居中） | 任务目标进度条 |

#### 2.5.2 交互规范
- **左键单击**：选择单位 / 点击 UI 按钮
- **右键单击**：移动指令 / 攻击指令（点击敌单位）
- **框选**：左键拖拽矩形多选
- **热键**：1-9 编组，Q 托管，W/A/S/D 长按移动

#### 2.5.3 状态反馈
- **血条颜色**：绿色（>66%）→ 黄色（33-66%）→ 红色（<33%）
- **热量条**：蓝色渐变 → 红色闪烁（>90%）
- **弹药计数**：数字显示剩余发数，归零后变灰
- **NO LOS 标记**：目标单位头顶显示红色叉号

## 3. 非功能需求

### 3.1 性能指标
| 指标 | 目标 | 测量方法 |
|------|------|----------|
| 帧率 | ≥30 FPS（1280×768） | 20 单位 + 复杂地形场景 |
| 单位响应延迟 | ≤100ms | 点击到路径寻找启动 |
| AI 决策周期 | 每 500ms 一次 | 10 个 AI 单位同时运行 |
| 内存占用 | ≤512MB | 最大地图 + 24 单位 |

### 3.2 兼容性
- **操作系统**：Windows 98/2000/XP（原版）；现代移植需支持 Win10+/macOS/Linux
- **显卡**：Direct3D 7.0 兼容（原版）；现代移植用 OpenGL 3.3+ / Vulkan
- **分辨率**：800×600 至 1920×1080（UI 自适应缩放）

### 3.3 可访问性
- **色盲模式**：红绿替换为蓝黄（敌我单位标识）
- **字幕**：过场动画语音配字幕
- **键盘操作**：所有功能可通过键盘完成（无需鼠标）

## 4. 用户故事

### US-01：战术微操专家
> **作为**战术玩家  
> **我想要**利用地形高差隐藏受损单位  
> **以便**避免被集火击毁，同时高地单位压制敌军

**验收标准**：
- 低地单位被高地形遮挡时，敌军不开火并显示 NO LOS
- 高地单位对低地目标命中率提升 10%
- 单位移动到高地时，战术地图显示视野扩大

### US-02：资源管理大师
> **作为**策略玩家  
> **我想要**平衡武器开火频率与热量积累  
> **以便**保持火力输出而不关机

**验收标准**：
- 热量条实时显示累积速度（每秒 +X%）
- 达到 100% 时单位强制关机 10 秒（无法移动/攻击）
- 散热片数量影响冷却速度（每片 -5%/秒）

### US-03：装配优化师
> **作为**硬核玩家  
> **我想要**测试不同武器配置的 DPS  
> **以便**找到最优化的机甲装配方案

**验收标准**：
- 装配界面显示计算后 DPS（伤害/秒）
- 显示有效射程（命中率 >50% 的距离）
- 保存 10 个自定义配置预设

### US-04：剧情沉浸者
> **作为**剧情玩家  
> **我想要**通过任务简报了解战场背景  
> **以便**理解战术目标的战略意义

**验收标准**：
- 任务前播放过场动画（30-90 秒）
- 简报包含地图标注（目标点/敌军预估位置）
- 任务后根据表现解锁不同剧情分支

```python
{
    "id": "px-01",

        "CT": 50, "LT": 30, "RT": 30,

    },

    "weapons": [
        {"slot": 0, "type": "PPC", "ammo": null},
        {"slot": 1, "type": "LRM-20", "ammo": 180}
    ],
    "heat_level": 0.0,             # 当前热量 0-100%
    "heat_sinks": 20,              # 散热片数量
    "speed": 64.0,                 # km/h
    "position": {"x": 320, "y": 480},
    "heading": 0                   # 朝向 0-7（8 方向）
}
```

#### Weapon（武器）
```python
{
    "type": "PPC",
    "category": "ENERGY",          # BALLISTIC/ENERGY/MISSILE
    "damage": 10,
    "range_px": 540,
    "heat": 10,
```

## 6. 技术约束

### 6.1 原版技术栈（2000 年）
- **引擎**：自研 3D 引擎（Direct3D 7.0）
- **脚本**：ABL（Automatic Behavior Language）
- **资源格式**：.fit（FitIni）+ .pak（LZ 压缩）+ .ase（3DS Max）

### 6.2 现代移植建议
- **渲染**：OpenGL 3.3+ / Vulkan（向后兼容低端硬件）
- **脚本**：保留 ABL 解释器（Lua 重写可能破坏原版任务）
- **资源**：保持 .fit/.pak 兼容（工具链转换为 JSON 可选）
- **网络**：添加多人对战（原版为单机）需设计同步协议

## 7. 风险与依赖

### 7.1 技术风险
| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| ABL 脚本逆向不完整 | 任务逻辑缺失 | 优先移植核心战斗系统，剧情任务后补 |
| 原版资产版权问题 | 无法直接使用贴图/模型 | 使用程序化生成 + 社区开源资产替代 |
| 性能瓶颈（单线程 AI） | 大规模战斗卡顿 | 多线程改造 AI 决策，物理/渲染保持单线程 |

### 7.2 依赖项
- **硬件**：支持 OpenGL 3.3 的 GPU（2010 年后集显）
- **数据**：官方 MC2 资产包（需玩家提供正版副本）
- **库**：SDL2（窗口）+ Freetype（字体）+ Ogg Vorbis（音频）
