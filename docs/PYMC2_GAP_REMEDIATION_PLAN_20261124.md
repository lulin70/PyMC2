## 2. 硬约束（每波必须满足）

1. **四项门禁全绿**：`ruff format` + `ruff check` + `MYPYPATH=src mypy src/pymc2` + `SDL_VIDEODRIVER=dummy pytest -q`
   - 事故记录（2026-11-26）：CI 因纯文档提交连续 5 次失败——ruff format 会重排 MD 内嵌 Python 代码块，而 `[tool.ruff.lint].exclude` 不作用于 format，且 ruff 0.17.5 的 `[tool.ruff.format].exclude` 失效（对照实验：连 docs 下 .py 也不排除）。修法：exclude 上移全局 `[tool.ruff]`（file_resolver 层，lint/format 同时生效）。教训：校验工具自身的配置也需按「每次提交全量门禁」验证，文档提交也要跑门禁。
2. **行为保持**：存量测试零语义改动；flat 模式渲染逐字节一致（回归钉）
3. **资产零入库**：MC2 官方资产只进 `~/.pymc2/mc2-assets`，仓库只有解析代码与程序化回退
4. **CI 远端确认**：每波提交推送后盯守 GitHub Actions 绿灯再收口

## 3. E2E 测试计划（模拟真实用户，发布前必做）

每阶段结束执行一轮「真实用户路径」切片测试，截图存 `docs/assets/uat_phaseN/`：

- **Phase 1（W1-W2 后）**：开局 → 简报目标阅读 → 框选编队 → 右键移动 → 装配界面改配置 → 出击 → 击毁目标 → 结算目标达成。全流程零崩溃、目标进度正确。
- **Phase 2（W3-W7 后）**：hills 模式斜投影下完成一次完整交战——镜头滚到高地、确认建筑立面可见、选中机甲行走动画播放、信息窗口护甲随受击变化、音效/特效触发、存档读档恢复战局。
- **Phase 3（W8 后）**：原版 mc2_01.pak + ABL 脚本任务全流程：增援按脚本时机出现、目标链推进、驾驶员分配影响命中率（统计采样 ≥50 次开火）。
- **Phase 4（W9 后）**：战役链 .arm 三连任务 + 经济闭环（修理/战利品/整备）跑通。

## 4. 排序约束与风险控制

1. **斜投影（W3）必须在行走动画（W5）之前**——否则朝向帧按旧投影渲染后返工。
2. **W4 高风险**：先做 PoC（30° 仿射变换 + 单帧截图对照 MC2），用户验收观感后再铺开拾取/命中/LOS 换算；保留 `--projection top` 回退开关。
3. **W3 装配编辑器**：pygame_gui 依赖需先评估许可与体积；降级方案 = 文本列表选择界面。
4. **W9 ABL**：不逆向官方字节码，先做 DSL→字节码自编译器；失败退路 = 手工移植 20 个任务脚本。
5. **音频（2.26）资产缺口**：官方音效不可入库，用程序化合成（pygame.sndarray 生成）或 CC0 音源，Wave 波次内 PoC。
