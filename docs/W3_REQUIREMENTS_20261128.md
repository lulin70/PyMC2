## 1. 问题陈述

PyMC2 当前为纯顶视正交投影（0° 俯视，无透视）：地形平面感、建筑只见屋顶、无纵深。MC2 原版为固定斜视角 3D 场景（28-60° FOV + 透视缩放）。这是**架构级视觉差距**（差距分析 2.5，工作量 6-8 人天，高风险），且存在硬排序约束：

- **必须先于 W5 行走动画**——朝向帧需按新投影角渲染，顺序颠倒即返工（§1 排序决策 1）
- **M2 里程碑关键决策点**（W3-W7 后）——斜投影观感对照 MC2 截图确认，W3 不交付则 M2 无法评估
- **Phase 2 E2E 切片**（W3-W7 后）——hills 模式斜投影下完整交战为必经场景

## 2. 范围

### In Scope（MVP：2D 仿射变换 PoC）
1. 投影变换核心模块（世界坐标 ↔ 屏幕坐标双向，固定倾角 30° 仿射）
2. 渲染链路接入（地形/单位/装饰/标记按斜投影绘制）
3. 点击拾取逆变换（屏幕坐标 → 世界坐标，误差 ≤1 tile）
4. 顶视开关回退（`--projection top/isometric`，缺省 top）
5. 面板/HUD 保持屏幕空间正交（不随地形变形）

### Out of Scope（远期/后续波）
- 透视深度缩放（按距离缩放，MC2 完全体 28-60° FOV 连续可调）——MVP 用固定 30° 仿射
- 建筑立面/穹顶绘制（W6+ 建筑系统）
- 朝向帧按新投影角重渲染（W5 行走动画前置任务，斜投影落地即解锁）
- 顶点光照与阴影（2.6，独立差距项）
- 命中判定/LOS 换算——**MVP 决策：逻辑层世界坐标不变**，投影仅渲染层，命中/LOS/移动零改动（见 FR-6）

## 4. 功能需求与可量化验收标准（Exit Gate 核心）

### FR-1 投影变换核心模块
- **FR-1.1**: 新建纯函数模块（无 pygame 依赖）：`world_to_screen(x, y, height, cam)` 与 `screen_to_world(sx, sy, cam)` 双向变换；仿射公式 `screen_y = world_y × 纵向压缩 − height × 倾斜分量`（压缩系数与倾斜分量按 30° 倾角定值，P3 设计确认常量）
- **FR-1.2**: 验收 — roundtrip 恒等：平坦地形（height=0）下 `screen_to_world(world_to_screen(p))` 与 `p` 距离 ≤1 tile（数值断言，含四角与中心采样点）
- **FR-1.3**: 验收 — `top` 模式下 `world_to_screen` 与存量实现输出逐点相等（回归钉）

### FR-2 渲染链路接入
- **FR-2.1**: Renderer 全部实体绘制走投影模块单一入口（地形表面、机甲/载具/炮塔、装饰、移动标记、攻击高亮）；禁止散落式坐标换算
- **FR-2.2**: 验收 — isometric 下高程台阶位移方向正确：高地 tile 绘制位置高于相邻低地 tile（E2E 截图目视 + 程序断言 `screen_y(高地) < screen_y(低地)`）
- **FR-2.3**: 验收 — 单位绘制排序保持遮挡正确：`y` 排序键语义不变（(elevation, y)），斜视角下近处单位遮挡远处（E2E 截图目视）

### FR-3 点击拾取逆变换
- **FR-3.1**: 主循环鼠标输入（框选/右键移动/键盘编队锚点）经逆变换恢复世界坐标；isometric 下忽略高程项的逆变换近似误差 ≤1 tile
- **FR-3.2**: 验收 — E2E：斜视角下对指定机甲屏幕位置点击 → 该机甲选中（程序断言 `selected.id`）
- **FR-3.3**: 验收 — E2E：斜视角下右键目标 tile 屏幕位置 → 机甲 `move_target` 落在该 tile 或相邻 1 tile 内

### FR-4 顶视开关回退
- **FR-4.1**: CLI 参数 `--projection {top,isometric}`，缺省 `top`；`--demo`/交互模式均生效
- **FR-4.2**: 验收 — `top` 模式全链路输出与 W2 收口版**逐字节一致**（flat 渲染回归钉：E2E 截图像素 diff = 0）
- **FR-4.3**: 验收 — isometric 模式 E2E 截图 3 张存 `docs/assets/uat_w3/`：isometric 全景（hills）、isometric 选中机甲、top 基线对照

### FR-5 面板/HUD 屏幕空间正交
- **FR-5.1**: HUD 面板（状态行/任务面板/信息窗口）与底部结算面板不参与地形投影变换，保持屏幕空间原样
- **FR-5.2**: 验收 — isometric E2E 截图中面板区域像素与 top 模式对应区域 diff = 0

### FR-6 兼容性硬约束
- **FR-6.1**: **逻辑层零改动**：命中判定/LOS/移动/热量/伤害全链路使用世界坐标，投影模块不进入 `services/`/`domain/` 依赖方向（architect 评审项：依赖单向 presentation → domain）
- **FR-6.2**: 存量 733 passed 零语义改动；isometric 不新增随机源
- **FR-6.3**: MC2 资产只读；无资产环境（程序化绘制）下 isometric 同样可用

## 5. 非功能需求

| NFR | 目标 |
|-----|------|
| 性能 | isometric 渲染 60 FPS（变换为纯算术 O(1)/实体；地形表面预构建 + 整体变换，不逐帧重算） |
| 可测试性 | 投影模块纯函数覆盖率 ≥80%；双向变换含数值断言（不依赖截图目视） |
| 可维护性 | 投影常量集中单处定义（倾角/压缩系数/倾斜分量），禁止魔法数字散落 |
| 兼容性 | top 模式为缺省且逐字节回归钉住；isometric 故障不阻塞游玩（FR-4.1 回退路径） |

## 6. 依赖与风险

| 项 | 类型 | 说明 |
|----|------|------|
| 渲染架构级触碰 | **高风险** | 地形表面预构建 + 整体 y 缩放方案 vs 逐 tile 变换需 P3 权衡（PoC 性质，失败退路 = 维持顶视只做光照优化） |
| 拾取逆变换高程项 | 技术缺口 | 逆变换忽略高程产生系统误差，≤1 tile 验收定标；超差则 P3 引入一次高程查表修正 |
| 相机钳制 | 技术 | isometric 下地图有效屏幕高度变化，钳制边界需按压缩系数重算 |
| W5 朝向帧 | 排序约束 | W3 收口即解锁 W5；若 W3 失败退路启用，W5 朝向帧按顶视渲染 |
| 6-8 人天预算 | 排期 | FR-1 投影模块 ≈1.5 天，FR-2 渲染接入 ≈3 天，FR-3 拾取 ≈1.5 天，FR-4/5 开关+面板+回归 ≈2 天 |

## 7. 四角色评审结论

| 角色 | 结论 | 意见 |
|------|------|------|
| architect | ✅ 通过 | 「逻辑层世界坐标不变 + 投影仅渲染层」决策正确，将 §5.1 技术挑战 3（命中/LOS 换算）消解为零；依赖方向单向性入 FR-6.1 可静态校验（mypy import 约束）。建议 P3 明确地形表面变换方案选型（整面缩放 vs 逐 tile） |
| tester | ✅ 通过 | FR-1.2 roundtrip 数值断言 + FR-4.2 逐字节 diff 为强回归钉；建议 P7 补充相机边缘钳制（地图边界外点击）与高差极端 tile（ELEVATION_MAX）用例 |
| security | ✅ 通过 | 无新增输入面（CLI 枚举参数 + 既有鼠标输入），无文件 IO，无依赖引入；风险低 |
| ui-designer | ✅ 通过 | FR-5 面板正交符合 MC2 心智模型（面板始终屏幕空间）；建议 isometric 压缩系数选型对照 MC2 截图（P3 视觉校准点，M2 里程碑预演） |

**P1 Exit Gate 检查**：FR-1 至 FR-6 验收标准全部可量化（数值断言/像素 diff/E2E 截图）→ **通过，进入 W3-S2（P3 技术设计）**

**P9 执行修订留痕（2026-11-28）**：FR-5.2「面板区域像素 diff = 0」验收方法修订——程序化 HUD 为地形上的文字（无不透明底板），背景像素必然随投影不同；改判为 HUD 文本调用序列跨投影逐条一致（_RecordingFont 捕获）+ 目视无变形。验收强度等价（面板链路不经投影的证明），详见测试计划 §3.1。
