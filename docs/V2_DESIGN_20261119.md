### 1.1 机甲受损变体精灵：远端不存在静态 TGA 变体

| 目标 | 探测结果 |
| --- | --- |
| Data/TGL/256/ | **远端不存在该目录**（本地此前也是 0 张；256 优先扫描仅对本机历史 checkout 有意义） |
| Data/TGL/128/ 机甲精灵 | 仅 4 张静态卡：`MadcatRGB.tga` / `ThorRGB.tga` / `UrbanMechRGB.tga` / `JagermechRGB.tga` |
| 上述 4 台 dam 变体 TGA | **零命中**（`TGL/(128\|256)/.*dam` 与四机甲名交集为空） |
| 受损外观的真实载体 | `Data/TGL/*.ase`（3DSMAX ASCII 动画场景）：`MadcatFallBackwardDam.ase`、`MadCatFallForwardDamL1.ase`、`thorFallbackwardDam.ase` 等；`Data/TGL/madcat.ini`（FITini）经 `[TGLData]` 引用 FileName0/FileName1 + ShadowName |
| Data/Art 立绘 | `MCL_MC_{MadCat,Thor,UrbanMech,Jaegermech}_{A,B}.tga`（无受损态） |

结论：MC2 原版机甲受损外观 = .ase 动画帧序列 + 实时损伤叠加，**不是独立静态精灵**。
ASE 解析（节点/材质/帧变换）远超本 Wave 范围（V1 渲染管线是单帧静态 blit）。
→ 机甲受损变体渲染走「变体 stem 派生 + 优雅回退」：索引能命中受损变体就切换（合成
fixture 与未来可能的社区提取卡均可命中），命中不了回退现状精灵，渲染输出零风险。

## 2. .fit 解析器设计（新增 src/pymc2/infrastructure/fit_parser.py）

**最小化原则**：只解析渲染管线消费得上的字段；不为解析而解析。

- 解析目标（`FitDefinition` frozen dataclass）：
  - `object_type_num: int` —— `[ObjectClass] ObjectTypeNum`（2=机甲，区分物体类别）；
  - `name: str` —— `[ObjectType] Name`（显示名）；
  - `appearance_name: str` —— `[ObjectType] AppearanceName`（**贴图/精灵引用**，小写化
    存储后可直接喂给 `MC2AssetPack` 匹配链）；
  - `extent_radius: float` —— 物理半径（渲染尺寸参考）；
  - `destroyed_object: int | None` —— 摧毁形态对象类号（残骸形态语义，V3+ 消费）；
  - `explosion_object: int | None` —— 爆炸形态对象类号（V3+ 消费）。
- 裁剪记录：`[MechProfile]` 三字段（destructdamage/explosiondamage/explosionradius）是
  战斗侧数值，PyMC2 有自己的伤害体系，解析无收益 → 不解析；`ProfileName` 与 Name 重复
  → 不解析。`ExtentRadius` 本 Wave 解析不消费（所有机甲恒 12，渲染尺寸暂固定格子），
  留作 V3 按半径缩放精灵的接口。
- 语法面（对齐实测格式）：`[Section]` 行 / `type Key = Value`（`l`=int、`f`=float、
  `st`=带引号字符串）/ `//` 注释剥离 / 空行跳过 / `FITini`、`FITEnd` 哨兵行跳过。
- 容错：非 FITini 文本（缺 `FITini` 头）抛 `FitParseError`（带行号语义的统一异常）；
  未知键忽略（官方文件注释行混入不致命）；缺 `AppearanceName`/`Name` 报错（渲染必需）。
- 编码：按 ASCII/latin-1 容错读取（实测纯 ASCII + CRLF；`Path.read_text` 后统一按行
  解析，CRLF 由 `str.splitlines()` 天然消化）。
- 与 pack 的关系：**独立模块零耦合**——`MC2AssetPack` 不自动扫描 Data/Objects（1196 个
  文件逐个解析不划算，且本项目机甲 id 体系 px-01/ex-01 与 .fit Name 体系不同名）。
  V3 候选：以 AppearanceName 替换 `CHASSIS_SPRITE_NAMES` 硬编码映射表的校准源。

## 3. 受损变体索引 + HP 阈值渲染

### 3.1 MC2AssetPack（mc2_assets.py 扩展）

- `resolve_mech_sprite(chassis_kind, *, damaged=False)`：damaged=True 时在候选名后追加
  变体词派生（`base + "dam"` → `base + "x"`，对齐环境物件命名约定：MadCatDam / MadCatX），
  先查变体、未命中回退基名候选链（与现状完全一致）；结果仍走解析缓存。
- `scaled_mech_sprite(chassis_kind, size_px, *, damaged=False)`：缓存键从
  `(kind, size)` 扩为 `(kind, damaged, size)`，旧键不进缓存故存量行为/缓存命中不变。
- 装饰 `resolve_environment` V1 接口不动（`_x`/`_dam` kind 后缀派生已覆盖 A_*Dam/X 变体）。

### 3.2 Renderer（renderer.py 扩展）

- 模块常量 `MECH_DAMAGED_HULL_RATIO = 0.5`：`hull_ratio <= 0.5` 且存活 → 请求受损变体。
- `_mech_sprite` 增加 damaged 分支：无资产包（现状全程序化）与无变体（回退基名）路径
  输出与现状完全一致——阈值切换只在「资产包既有精灵」链路上多一层解析，无资产时零改动。
- 环境装饰不接入受损态（偏离见 §5）：装饰无 HP/战斗状态，机制上没有触发点。

## 5. 偏离与裁剪清单（相对任务简报）

1. **机甲受损变体 TGA 远端不存在**：简报预期「探测 MadcatRGB_dam 之类」——实测不存在，
   受损外观是 .ase 动画。改为派生匹配 + 回退管线（fixture 验证），真资产观感等社区
   提取卡/后续资产补齐，接口一次到位。
2. **.ase / .ini 不解析**：3DSMAX ASCII 动画场景解析远超静态 blit 管线（V1 语义），
   V2 不做；`madcat.ini` 的 FileName/ShadowName 引用体系与 V2 无消费点。
3. **.fit 裁剪 [MechProfile]**：战斗侧数值解析无收益；只留渲染相关六字段。
4. **环境装饰不接入受损态**：装饰是纯视觉撒点（V1 定案：不阻挡、不参与命中），无 HP
   与受击状态，没有触发受损渲染的状态源；`resolve_environment("tree_x" 等) `接口 V1
   已暴露可手工查询。留 V3：若引入可破坏物件实体再接。
5. **下载范围**：仅 4 个 .fit 入本机缓存（TGA 零新增——四机甲 RGB 与环境变体本地已齐，
   远端机甲无变体 TGA 可下）。

### 6.2 实现要点与坑

- **FITini 类型前缀在行首**：官方格式是 `st Name = "UrbanMech"`（前缀+键+值），首版把
  前缀误挂在值上解析导致 `name` 键缺失，mypy/pytest 双双拦下后修正为
  `_parse_entry`（kind 校验 l/f/st，单键损坏返回 None 不致命）。
- **缓存分键**：`_resolve_cache`/`_scaled_cache` 键从 `str`/`(str,int)` 扩为
  `(str,bool)`/`(str,bool,int)`——mypy 4 处 index 报错暴露，修复后存量调用路径
  （damaged=False 默认值）行为与缓存命中不变。
- **真实 .fit 人工验证**（不入仓库）：解析器对 `~/.pymc2/mc2-assets/Data/Objects/`
  四文件输出全部正确（object_type_num=2、appearance_name 小写化、destroyed=101、
  explosion=41、extent=12.0），与设计文档 §1.3 实测结构一致。
- e2e 断言像素选取：机甲精灵 32px 覆盖出生 tile，断言点取中线下方 8px 避开水平
  弹道（双方同排 y≈336）；残骸断言点取中心右偏 6px 避开两条交叉裂纹对角线。
